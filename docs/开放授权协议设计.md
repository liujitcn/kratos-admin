# 开放授权协议设计

开放授权用于外部开发接口，不替代管理端用户登录，也不复用三方登录 `OauthService`。外部开发接口使用 `/api/v1/oauth/` 路径前缀；管理端通过 `OauthClientService` 维护客户端。

当前仓库只提供授权客户端管理和令牌签发，不内置 `/api/v1/oauth/` 业务接口。接入方需要通过外部 Go 模块贡献带有该路径前缀的 Proto、OpenAPI 和服务；未接入外部业务模块时，管理端的可授权 API 列表为空，客户端不能用于调用业务接口。

管理端页面位于 `frontend/admin/packages/modules/system/src/views/base/oauth-client`，可查询授权 API、创建/编辑/删除客户端、启停客户端和复制完整凭据。完整凭据只在管理端按需读取，`client_secret` 和 `crypto_key` 不进入列表响应。

## 数据模型

只新增 `oauth_client` 表：

- `client_id`、`client_secret`：客户端凭据。
- `tenant_id`：客户端绑定租户，所有客户端数据和 Token 权限使用该租户的数据权限。
- `crypto_type`、`crypto_key`：调用方协议加密元数据，由开放授权 HTTP Filter 在请求绑定前读取并执行加解密。
- `ip_whitelist`：逗号分隔的精确 IP 或 CIDR。
- `api`：允许访问的 `base_api.operation` JSON 数组，不建立关联表，和菜单 API 字段保持一致。
- `status`：客户端启停状态。

## 协议流程

1. 客户端向 `POST /api/v1/base/oauth/client/token` 提交 `client_id`、`client_secret` 和可选的 `grant_type=client_credentials`。
2. 服务校验凭据和客户端状态，使用现有 JWT/Redis 令牌管理器签发 Bearer Token；Token 的角色编码为 `client_id`，`uid/rid` 使用负数客户端身份空间，避免与用户令牌缓存键冲突。绑定默认租户时使用 OAuth 专用租户编码，避免默认租户的跨租户管理语义绕过数据隔离。
3. 管理端创建或修改客户端时，将 JSON API 列表转换成默认租户下该客户端角色的 Casbin operation 策略。
4. 客户端携带 Bearer Token 调用 `/api/v1/oauth/` 接口。HTTP OAuth middleware 只在令牌角色命中 `oauth_client.client_id` 时执行，分别校验客户端身份、状态、来源 IP 和当前 operation + HTTP method 是否在 API JSON 白名单中。
5. 普通用户令牌不会命中客户端表，直接沿用现有用户认证和 Casbin 链路。

## 数据加解密

客户端创建后，管理端会按算法生成匹配格式的 `crypto_key`：

| `crypto_type` | `crypto_key` 格式 | 密文格式 |
| --- | --- | --- |
| `sm4` | Base64 编码的 16 字节密钥 | Base64(`12 字节 nonce || ciphertext || 16 字节 GCM tag`) |
| `aes` | Base64 编码的 32 字节密钥 | Base64(`12 字节 nonce || ciphertext || 16 字节 GCM tag`) |

调用顺序如下：

1. 调用 `POST /api/v1/base/oauth/client/token`，使用 `client_id` 和 `client_secret` 获取 Bearer Token。
2. 对 `/api/v1/oauth/` 下的 `POST`、`PUT`、`PATCH` 请求，将正常 JSON 请求体按客户端算法加密后 Base64 编码，作为整个 HTTP body 发送；`GET`、`DELETE` 的 query/path 参数保持明文。
3. 请求必须携带 `Authorization: Bearer <access_token>`。服务端先验证客户端 Token，再读取客户端算法和密钥，在 Proto HTTP body bind 之前解密，因此业务 Service 收到的仍是普通请求对象。
4. 成功的 2xx 响应会加密。当前 ProtoJSON 直出响应整体编码为 JSON 字符串形式的 Base64 密文；如果接入方使用 `{"code":200,"data":...}` 包装响应，则只加密 `data` 字段，`code`、`msg` 保持明文。
5. 4xx/5xx 错误响应不加密，便于定位凭据、IP、权限或密文格式错误。

HTTP Filter 在 `backend/internal/module/module.go` 注册，HTTP 包装实现位于 `backend/internal/server/middleware/oauth/crypto.go`，算法实现位于其 `crypto/` 子目录。它位于生成的 Proto HTTP 路由外层；不能只使用 operation Service middleware，因为后者执行时请求体已经完成绑定。

## 边界

API 选项、保存校验和运行时拦截器都会拒绝非 `/api/v1/oauth/` 的接口，避免把管理端、应用端或基础登录接口授权给开发客户端。停用、修改白名单或删除客户端后，新的请求立即受影响；删除同时清理 Casbin 策略。

客户端只需要保存管理端返回的 `client_id`、`client_secret`、`crypto_type` 和 `crypto_key`，不要把 `crypto_key` 写入前端仓库或日志。更新客户端算法会重新生成密钥，旧密钥立即失效；客户端应重新读取凭据后再发起调用。
