# 漏洞整改实施计划

依据：2026-11-03 校园生活服务客户运营平台 V0.0.3 安全测试报告及本次对话确认的 11 项整改方案。

## 目标与边界

- 修复当前基础仓库能够落实的脚本执行、账号命名、日志、版本、密码、配置与数据保护问题，核对 SSE 授权边界，并记录宿主业务、生产数据和部署环境仍需完成的事项。
- 管理端协议使用独立的配置、展示与确认流程，不消费或覆盖移动端协议；复用现有配置管理和认证基础设施。
- 沿用 Go/Kratos、Proto、Vue、现有加密与脱敏库；不引入新依赖或重复的安全框架。
- 不手改生成产物；生成统一在手写代码完成后运行。保留所有无关现有改动；按用户本次授权提交并推送源码，包发布和部署另行执行。

## 实施顺序

1. 脚本安全：测试先覆盖进程、文件和网络能力拒绝；统一执行边界，试运行只接受已保存 ID，同步脚本页面调用。
2. 账号与审计：统一保留用户名校验，修正初始化账号；扩展业务操作审计，保证六个月以上留存与失败回退。
3. 管理端协议：专属配置与登录确认、公开可读的协议页面、确认留痕，覆盖密码和第三方登录入口；移动端协议保持独立。
4. 公共边界与数据：检查 SSE 租户及用户授权、凭据和敏感字段存储、历史数据处理、密码与配置保护；展示实际服务版本。宿主缺失的集群 SSRF 代码不以未接入 helper 充作修复。
5. 统一补齐 Proto、生成产物、权限 SQL、四种语言与文档，运行检查并逐项记录报告对应状态。

## 验证

- 安全逻辑使用最小稳定的回归测试，先观察原实现失败，再运行修复后的针对性测试。
- 后端收尾运行 `go test ./...`，管理端运行 `pnpm lint:oxlint`、`pnpm type:check`；执行相关生成与国际化检查、`git diff --check`。
- 特别核对：已保存恶意脚本、跨租户事件重放、协议默认未选与版本变化、业务模块审计、明文残留及密钥轮换的数据可恢复性。
- 不自动轮换生产密钥、不连接报告目标执行攻击；生产凭据、存量数据和实际部署的复测单独留证。
