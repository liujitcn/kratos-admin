# 安全部署与存量修复

本页描述当前代码提供的控制和升级步骤。代码测试不替代受测环境的配置核对、凭据轮换、备份恢复或渗透复测。

## 配置与密钥

基础配置通过环境变量读取凭据；也可继续使用配置加载器已支持的 `ENC[...]` 密文。根密钥由现有 Key Provider 提供，不能把生产解密密钥与配置文件一起分发。

| 变量 | 使用位置 |
| --- | --- |
| `DATABASE_DSN` / `DATABASE_2_DSN` | 默认与完整配置中的数据库连接 |
| `POSTGRES_DSN` / `TIDB_DSN` | 对应驱动的可选配置 |
| `REDIS_PASSWORD` | Redis 认证 |
| `OSS_ACCESS_KEY` / `OSS_SECRET_KEY` | 对象存储 |
| `REGISTRY_TOKEN` | 完整配置中的注册中心 |
| `PPROF_PASSWORD` | 性能分析服务 |
| `LOGGER_ACCESS_KEY` | 完整配置中的云日志服务 |

仅配置实际启用的组件。数据库 DSN 应由秘密管理系统注入，避免在终端历史、进程参数和日志中展示。历史仓库或受测系统已经暴露的凭据需单独轮换；修改模板不会撤销旧凭据。

生产入口使用 HTTPS。密码继续使用一次性 RSA-OAEP/AES-GCM 字段传输保护与 bcrypt 哈希；保持密钥时效、nonce 和同次提交多字段校验。字段加密不能保护 HTTP 上的会话令牌。

## 脚本执行

脚本管理、草稿执行、按 ID 执行、九种语言和工作流脚本保留，执行迁移到独立工作进程。Linux 需要 `bubblewrap` 和用户、PID、网络、挂载命名空间；镜像已安装对应软件。部署的容器安全策略必须允许所需命名空间，且服务应使用非 root 用户。沙箱初始化失败时返回错误，不回退到服务进程执行源码。

每次执行使用独立目录和环境，限制 4 个并发执行、5 秒总预算、1 MiB 结果及控制台输出；Linux 还限制 tmpfs、内存和进程资源。超时清理整个执行组。macOS 使用系统 `sandbox-exec`，Linux 的内存与进程限制以 Linux 运行结果为准。

现有业务依赖的资源由部署配置明确授权：

| 变量 | 格式及用途 |
| --- | --- |
| `SECURITY_SCRIPT_READ_PATHS` | 逗号分隔的只读绝对路径 |
| `SECURITY_SCRIPT_WRITE_PATHS` | 逗号分隔的可写绝对路径 |
| `SECURITY_SCRIPT_COMMANDS` | 逗号分隔的可执行程序绝对路径 |
| `SECURITY_SCRIPT_ALLOWED_HOSTS` | 允许的完整域名，可限定端口 |
| `SECURITY_SCRIPT_ALLOWED_CIDRS` | 允许的目标网段，内网服务必须显式授权 |

路径中的 `{tenant_id}`、`{user_id}` 由当前认证身份展开，不从脚本输入取值。授权目录应按租户或用户分离，不能授权主服务配置、根密钥目录或其他任务目录。命令依赖的文件也需要分别授权。网络请求通过主服务代理校验目标和 DNS，工作进程不能直接连接外部网络或任意宿主套接字。

## 实时订阅和来源地址

SSE 在连接及历史回放前执行流声明的资源授权。平台管理员和明确获得项目授权的用户继续使用授权范围；默认租户普通用户不再自动拥有全部项目。流未绑定授权器时拒绝请求；每 30 秒重新检查会话和资源范围，退出、令牌撤销或授权变化后关闭连接。长连接不会重新扩大回放范围。

`SECURITY_TRUSTED_PROXY_CIDRS` 使用逗号分隔的代理 CIDR。只有 TCP 对端属于受信代理时才从右向左解析转发链，未配置或配置无效时使用 TCP 对端。反向代理应覆盖外部传入的转发头；访问日志、业务审计和登录来源限制共用此规则。

## 账号升级

新增账号与个人改名共用保留名称校验，大小写变体同样拒绝。新装平台管理员名为 `platformoperator`，新租户管理员名为 `tenantoperator`，初始账号仍需首登改密。`SECURITY_RESERVED_USERNAMES` 可补充产品正式名称和缩写。

存量账号按稳定用户 ID 更名，保留角色、组织、项目授权和历史关联。先核对旧名的外部使用方，再由部署设置一次性清单，例如：

```text
SECURITY_ACCOUNT_RENAMES={"2":"platformoperator"}
```

清单只处理保留名称或已经完成同一次更名的记录。数据库事务成功后撤销旧令牌；撤销失败可用相同清单重试。完成核对后移除该变量，避免以后每次启动都撤销这些账号的令牌。

## 敏感字段与历史数据

新增租户联系人姓名、电话的入库保护及列表、详情出库脱敏。编辑时核对原样掩码并保留原文；真实新号码仍须通过服务端校验。原文查看只接受编译注册的模型及启用的字段策略，同时应用主记录的数据范围和租户检查；项目字段实时读取既有四维项目授权，保留合法跨租户查看并响应授权撤销，记录敏感访问审计。

升级已有数据库时，修改 `v0.0.1` 初始化脚本不会自动重放。先备份主表、保护旁表、配置及相应密钥版本，补齐 `base_redact_rule.up.sql` 中所需策略后，在隔离环境检查恢复，再设置：

```text
SECURITY_BACKFILL_SENSITIVE_DATA=1
```

启动过程按注册模型、每批最多 200 条记录执行事务回填。主表保存展示值，旁表保存加密原文和查询摘要；短姓名同样保护。重复执行校验已有密文和旁表，不重复加密。主旁不一致、密文损坏或掩码缺少原文时停止，不推测或覆盖原值。

直接加密字段无法仅凭外观区分历史明文与损坏密文。只有经备份和原系统核实的历史明文，才加入精确的表、列、记录 ID 清单，例如：

```text
SECURITY_LEGACY_PLAINTEXT_MANIFEST={"ai_provider":{"api_key":[3]}}
```

清单不包含原文，不要把“解密失败”直接当作“历史明文”。回填计数表示处理的记录数，已提交的批次允许重试；完成主旁对账及功能回归后移除这两个一次性变量。

普通读取、脱敏编辑、受控原文查看和现有查询入口均保留。回填前核对自定义策略是否涉及已有模糊查询、排序或统计；摘要只支持等值条件，不能将新策略直接套在需要明文模糊检索的字段上。备份和归档需保留主旁表及可用密钥，旧制品回退前先验证密文格式兼容性。

## 审计、协议和版本

账号、密码、跨模块变更、脚本执行、敏感原文查看及导出进入现有审计通道。脚本源码、输入输出、凭据和个人信息不进入审计快照。沿用回退文件、HMAC、补写和归档能力；验证故障补写及归档检索后再确认留存符合要求。

新装六类安全日志默认在线保留 365 天、归档保留 365 天，并启用归档任务。安全日志的可恢复总期限不得低于 184 天；检查实际的归档目的地、删除策略及定时任务，既有数据库不会自动替换旧值。

管理端、uni-app 和 Taro 提供协议查看和主动确认，默认不勾选。管理端缺少独立正文时回退应用端的 `privacyProtocol`、`serviceProtocol`；配置接口返回原文组合的 SHA-256 摘要作为 `agreementVersion`，同时返回宿主产品版本。升级清理缺少协议的旧缓存，应用端协议更新会使管理端缓存失效。

客户端确认随本次登录、OAuth 票据和 MFA 请求携带。服务端将声明与当前协议摘要核对，最终登录成功后记录主体、租户、时间、来源和摘要；自动化客户端没有声明时不会生成同意记录。必须由产品负责人配置符合实际采集行为的正式协议，示例正文不能作为法务确认或生产验收。

升级验收同时包含正常功能与安全用例，至少覆盖脚本资源、合法跨租户订阅、联系人编辑、原文权限、协议查看及确认。数据库迁移、凭据轮换、真实集群和第三方登录验证均需在实际部署环境完成。
