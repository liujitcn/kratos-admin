# 租户项目授权

本文描述当前仓库中租户、项目和四类主体授权的实现。项目目录、授权合并和接口过滤均由本仓库后端维护。

## 数据模型

`base_tenant_project` 保存项目目录，`id` 即项目 ID。项目名称、编码、所属租户和启停状态只有这一张表负责维护。

`base_tenant_project_grant` 使用 `(tenant_id, subject_type, subject_id)` 联合主键。`subject_type` 为岗位、角色、直属部门或用户，`project_id` 保存 JSON 数字数组：

- `[0]` 表示目标租户当前和未来的全部项目；
- `[101, 102]` 表示指定项目；
- `[]` 或无记录表示当前主体没有直接授权；
- `0` 不能与其他项目 ID 混用。

## 授权合并

登录后，服务端按目标租户读取当前用户的岗位、角色、直属部门和用户授权并取并集。内置 `tenant` 角色的租户管理员自动获得本租户全部项目范围；其他主体必须通过四类授权配置获得范围。

任一有效来源为 `[0]` 时，该租户结果为全部项目；空的用户授权不会抵消其他来源。当前版本不继承上级部门，也没有拒绝规则。停用的租户、角色、部门或岗位不提供有效授权，普通租户主体不能获得跨租户范围。

项目范围在请求处理时从服务端重新计算，不固化到 JWT，也不信任客户端缓存。组织关系、角色状态或授权变更在下一次请求即可生效。

## 管理端行为

- 默认租户可维护全部租户的项目目录，并在列表中展示租户和项目列。
- 普通租户只能查看本租户已授权的项目。
- 项目创建、编辑、启停和删除只在项目目录页面提供，不由业务页面重复维护。
- 岗位、角色、部门和用户列表均通过共享授权弹窗配置项目范围。
- 保存授权会整体替换当前主体来源的数组，不修改其他来源。

## 接口与前端

后端服务位于 `backend/api/proto/system/admin/v1/base_tenant_project.proto` 和 `base_tenant_project_grant.proto`。管理端复用 `TenantProjectManager`、`TenantProjectSelect` 和 `ProjectGrantDialog`；业务页面通过项目选择器提交项目 ID，服务端再次校验当前用户的租户和项目范围。

应用端只接收当前身份可用的项目选项，不保存完整授权矩阵。任何写入、查询和导出接口都必须在 Biz 层执行同样的租户与项目校验。

## 初始化与验证

默认菜单、按钮、API 权限和演示项目统一维护在 `backend/migration/assets/v0.0.1/mysql`。新增字段或接口后按“Proto → 生成 → Service/Biz → 管理端 → 初始化权限”的顺序更新，并运行：

```bash
make gen
make check
make menu-sort
```

当前版本不迁移旧项目授权数据；重新初始化开发数据库时以 `v0.0.1` 的完整初始化资源为准。
