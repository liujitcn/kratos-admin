# 租户项目与四维授权

## 公共模型

Admin 管理 `base_tenant_project`，`id` 就是项目 ID，不再增加 `project_id`。业务模块以 `tenant_id + project_id` 关联公共项目，SCP 显示项目，Shop 可以显示门店。项目名称、编码和基础状态只有 Admin 一个权威来源。

`base_tenant_project_grant` 使用 `(tenant_id, subject_type, subject_id)` 联合主键，没有独立 ID。`tenant_id` 是授权目标租户，主体类型为 1 岗位、2 角色、3 直属部门、4 用户。`project_id` 保存 JSON 数字数组：`[0]` 为目标租户全部现在和未来项目，`[101,102]` 为指定公共项目主键，`[]` 或无记录为无直接授权。0 不得与其他 ID 混用。

## 合并和失效

登录后获取用户信息时读取当前用户的岗位、角色、直属部门和用户授权，按目标租户取并集。任一有效来源为 `[0]`，该租户结果为 `[0]`。空的用户授权不抵消岗位、角色或部门授权。第一版不继承上级部门，也不设置拒绝规则。

请求中的范围需要重新从可信服务端加载，不信任前端保存的用户信息，不将完整授权固化在 JWT。组织关系变化和授权撤销不应等到重新登录才生效。角色/部门停用不能继续提供有效授权，停用岗位不参与授权合并。普通租户主体不能获得跨租户授权。平台维护的 super 角色负责首次授权初始化，普通默认租户账号仍受授权约束。

## 展示与配置职责

默认租户展示租户/项目树以及租户、项目列；普通租户只展示项目。SCP 保留下游地址、同步源、同步任务、OAuth 配置与绑定功能，移除独立的项目创建、名称修改、基础启停与删除入口。

授权配置分别在岗位、角色、部门和用户列表进入共享弹窗。操作人必须有授权按钮权限，并且不能授予超出其有效范围的项目。授权保存整体替换当前来源的数组，不修改其他来源。

## 本地联合验证

开发时使用临时 Go workspace 同时引用 Admin backend、Admin api、cloud-scp backend 及当前 Core 源码。临时 workspace 不提交，不写入绝对路径 replace，也不在未授权时发布 tag 或 npm 包。最终发布依赖版本仍需按仓库正常发布流程更新。

不迁移历史业务数据，初始化结构和默认菜单直接维护现有初始化脚本。生成模型、协议、RPC 和 Wire 只使用各仓库 Make 目标生成。
