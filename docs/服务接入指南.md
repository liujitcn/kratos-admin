# 服务接入指南

本文用于在当前仓库新增或调整后端、管理端、uni-app 和 Taro 功能。所有接口、生成产物、权限和初始化数据必须在同一次改动中保持一致。

## 模块归属

| 能力 | Proto 目录 | 后端实现 | 前端归属 |
| --- | --- | --- | --- |
| 登录、MFA、文件、AI、消息公共能力 | `backend/api/proto/base/v1` | `backend/internal/biz/base`、`service/base/v1` | 三端 core 或 System |
| 系统管理 | `backend/api/proto/system/admin/v1` | `backend/internal/biz/system/admin`、`service/system/admin/v1` | 管理端 System |
| 应用端数据 | `backend/api/proto/system/app/v1` | `backend/internal/biz/system/app`、`service/system/app/v1` | uni-app/Taro core |
| AI 知识库 | `backend/api/proto/rag/admin/v1` | `backend/internal/biz/rag/admin`、`service/rag/admin/v1` | 管理端 RAG |

新增业务模块时，代码放在对应目录，不把业务逻辑写入宿主入口或公共 core。

## 后端流程

1. 先确认配置数据源和已有表结构；新增表先在开发库建立，再执行 `make -C backend gorm-gen`。
2. 在 `backend/api/proto` 定义 Proto、HTTP 路由、校验和 OpenAPI 描述。
3. 执行 `make -C backend api` 生成 Go、OpenAPI 和传输代码。
4. 实现 Service、Biz、Data 和任务；Service 只做适配，租户、权限、状态和事务规则放在 Biz。
5. 修改 Wire 或公共模块装配后执行 `make -C backend public-wire` 和 `make -C backend wire`。
6. 在 `backend/migration/assets/v0.0.1/mysql` 补齐菜单、按钮、API 权限、默认数据和多语言，不新增其他迁移版本。
7. 按受影响端生成 TypeScript RPC，并完成后端测试和三端检查。

Repository 查询优先使用生成的类型化 Query，不拼接运行时 SQL。错误按现有错误原因集合分类，并在 Biz 层补充业务上下文。

## 管理端流程

管理端页面统一使用 `ProTable + FormDialog + ProForm`。请求封装放在业务模块 `src/api`，类型和 RPC 使用生成文件，页面不直接访问底层请求库。

新增 System 或 RAG 页面时：

1. 在对应模块的 `src/views`、`src/api` 和 `src/rpc` 目录新增文件；
2. 在模块注册入口加入菜单、顶部工具或个人中心扩展；
3. 在模块语言包中补齐四种语言的相同 key 和占位符；
4. 同步初始化菜单、按钮和 API 权限；
5. 执行 `pnpm lint:oxlint` 和 `pnpm type:check`。

## 应用端流程

uni-app 和 Taro 页面放在所属模块的 `src/views`，通过模块注册函数声明 `pages`、`views` 和 `icons`。宿主只维护 `module-manifest.ts`，不手工提交构建插件生成的 wrapper 或页面配置。

请求统一放在模块 `src/api`，认证、刷新令牌、上传、SSE 和错误提示复用 core。页面只使用稳定 `viewKey`，不接受服务端下发的组件路径。

新增页面后同步：

- `pages.ts` 和模块注册入口；
- 页面语言包、静态资源和必要的 tab 配置；
- H5 与微信小程序的条件编译检查；
- `pnpm lint`、`pnpm tsc`，涉及 runner、CLI 或公开 exports 时再执行 `pnpm test` 和 `pnpm check:exports`。

## 生成命令

```bash
make -C backend api
make -C backend gorm-gen
make -C backend public-wire
make -C backend wire
make -C frontend ts-admin
make -C frontend ts-uni-app
make -C frontend ts-taro-app
make i18n
```

生成文件包括 `backend/api/gen`、`backend/internal/data/gen`、Wire、OpenAPI 和各前端 `src/rpc`，禁止手工修改。

## 交付检查

```bash
make gen
make check
make menu-sort
git diff --check
```

检查内容至少覆盖：Proto 路径与 `base_api.path` 一致、菜单组件路径存在、角色权限包含新增 API、语言包 key 一致、H5/微信入口可构建、租户和权限边界有回归测试。
