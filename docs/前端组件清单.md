# 前端组件与 Core 能力清单

本文以当前仓库代码为准，记录管理端 `@liujitcn/kratos-admin-core` 的组件、公共函数和运行能力，并补充 uni-app、Taro 的底座边界。文中的“公共”表示已经写入 npm `exports` 白名单，可以从已发布的 core 包导入；“内部”表示源码存在但没有公共子路径，不应跨包引用。

## 1. 范围与边界

| 范围 | 目录 | 责任 |
| --- | --- | --- |
| 管理端底座 | `frontend/admin/packages/core` | 启动、登录、MFA、OAuth、认证令牌、动态菜单、路由、布局、主题、国际化、公共组件和运行期 Store。 |
| 管理端业务 | `frontend/admin/packages/modules/*` | System、AI 及其他业务页面、业务 API、业务私有组件。 |
| uni-app 底座 | `frontend/uni-app/packages/core` | 应用端启动状态、页面框架和底部导航等公共能力。 |
| Taro 底座 | `frontend/taro-app/packages/core` | 应用端启动状态、页面框架和底部导航等公共能力。 |
| Taro UI | `frontend/taro-app/packages/ui` | NutUI 主题、图标和 UI 适配，不承载业务页面。 |

core 不包含个人中心、AI 助手和 System 管理页面。宿主需要在启动时注册业务模块，业务模块页面按 `<module>/<view>` 前缀解析。core 自带的固定静态页面键为：`login/index`、`error/403`、`error/404`、`error/500`、`error/pending`。

公共入口以 `frontend/admin/packages/core/package.json#exports` 为唯一依据。不要从业务包相对引用 `frontend/admin/packages/core/src`，也不要手动修改 `rpc`、`types/generated` 或发布目录 `dist/package`。

### 2.2 ProForm 字段类型

`ProForm` 通过 `ProFormField[]` 描述字段。`component` 当前支持以下类型：

| 类型 | 控件 |
| --- | --- |
| `input`、`password`、`textarea` | 普通输入、密码输入、多行文本。 |
| `yaml-editor` | YAML 语法编辑器。 |
| `input-number`、`color-picker` | 数字和颜色。 |
| `segmented`、`switch`、`checkbox` | 分段选择、开关、单个复选框。 |
| `select`、`cascader`、`tenant-select`、`dict` | 下拉、级联、租户和字典选择。 |
| `radio-group`、`checkbox-group`、`tree-select`、`transfer` | 单选、多选、树选择和穿梭框。 |
| `date-picker` | 日期/日期时间选择。 |
| `cron-expression` | 六段式 Cron 编辑器。 |
| `image-upload`、`images-upload`、`file-upload`、`files-upload` | 单/多图片和单/多文件上传。 |
| `rich-text` | WangEditor 富文本编辑器。 |
| `dynamic-list`、`kv-list` | 动态字符串列表和键值列表。 |
| `slot` | 由页面插槽自定义字段内容。 |

字段还支持点路径 `prop`、动态 `props`/`itemProps`/`options`、`colSpan`、强制换行、标签提示、后缀插槽、`visible`、规则和 `secret`。`secret` 为对象时，输入框眼睛会调用已注册的敏感字段查看处理器；`SecretInput` 是 ProForm 内部实现，不单独公开。

```vue
<FormDialog
  ref="dialogRef"
  v-model="visible"
  :model="formModel"
  :fields="formFields"
  :rules="rules"
  @confirm="handleSubmit"
  @closed="resetForm"
/>
```

`FormDialog` 和 `ProForm` 不调用业务接口。页面在 `confirm` 中执行校验、提交、关闭和刷新，关闭时显式重置模型和校验状态。

### 2.3 ProTable 列和实例

`ProTable` 的 `columns` 支持 Element Plus 表格列能力以及以下扩展：

- 搜索控件：`input`、`input-number`、`select`、`tenant-select`、`select-v2`、`tree-select`、`cascader`、`date-picker`、`time-picker`、`time-select`、`radio`、`switch`、`slider`。
- 列类型：`index`、`selection`、`radio`、`expand`、`sort`。
- 预置单元格：`image`、`status`、`actions`、`money`。
- 枚举/字典：`enum`、`dictCode`、`dictValueType`、`fieldNames`、`tag`、`isFilterEnum`。
- 页面配置：`isShow`、`isSetting`、`search`、`headerActions`、自定义 `render`/`headerRender`、多级表头 `_children`。

表格请求约定由 `requestApi` 返回 `{ data: { list, total } }`。推荐用 `buildPageRequest` 统一将 `page_num`、`page_size` 转换为数字。实例提供 `getTableList`、`search`、`reset`、分页切换、`clearSelection`、`getTotal`、`refreshEnums`，以及当前加载态、分页、查询参数、选中行和枚举缓存。

`cellType: "actions"` 会按行的 `hidden` 过滤按钮；可见操作超过三项时，编辑和删除优先保留在行内，其余进入“更多”菜单。操作列默认固定右侧并按当前页文案、图标和可见操作自适应宽度，页面可用 `width`、`minWidth` 或 `fixed` 覆盖。

```ts
import { buildPageRequest } from "@liujitcn/kratos-admin-core/table";

async function requestTable(params: Record<string, unknown>) {
  const response = await service.Page(buildPageRequest(params));
  return { data: { list: response.items ?? [], total: response.total } };
}
```

### 5.2 请求、认证和导航

| 入口 | 导出 | 功能 |
| --- | --- | --- |
| `request` | 默认 Axios 客户端 | 统一 API 前缀、Cookie 凭据、访问令牌注入、刷新令牌、结构化错误提示和登录过期处理。 |
| `request` | `requestBaseURL` | 当前请求基地址。 |
| `request` | `hasValidAccessToken`、`getRequestAccessToken`、`ensureAccessToken` | 判断、获取和按需刷新内存访问令牌。刷新只使用 HttpOnly Cookie，并携带 `X-Refresh-Token-Transport: cookie`。 |
| `request` | `handleAuthExpired` | 清理过期认证并跳转登录。 |
| `request` | `passwordChangeState`、`handlePasswordChangeRequired`、`clearPasswordChangeRequired` | 处理后端要求首次登录修改密码的状态。 |
| `navigation` | `router`、`isUnmatchedRoute`、`resolveFrontendRouteURL`、`navigateTo` | 路由实例、未匹配检测、前端地址解析和安全跳转。 |
| `navigation` | `router` 的动态路由守卫 | 登录态校验、菜单恢复、动态路由注册和未匹配页面兜底；内部 `resetRouter` 只由 core 路由实现使用，未作为 npm 子路径导出。 |

动态路由流程：登录后请求用户菜单和按钮权限，规范化相对路径，按模块视图注册表解析组件；未注册组件落到 `error/pending`，外链菜单不注册为 Vue 路由，AI 菜单受运行配置开关控制。

### 5.4 安全、OAuth、文件和通用工具

## 9. 维护与验证

新增或调整组件后，按以下顺序同步：

1. 更新组件源码和同目录 TypeScript 类型。
2. 需要跨包使用时，在 `packages/core/package.json#exports` 增加明确入口；不要直接暴露整个源码目录。
3. 运行生成/构建命令更新 `dist/package` 和 `types/generated`，禁止手写生成产物。
