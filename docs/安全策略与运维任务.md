# 安全策略与运维任务

## 登录安全

登录失败锁定仍按租户、账号和客户端地址隔离。部署时可通过环境变量增加来源策略：

| 变量 | 格式 | 说明 |
| --- | --- | --- |
| `LOGIN_POLICY_IP_BLACKLIST` | 逗号分隔 IP/CIDR | 命中即拒绝 |
| `LOGIN_POLICY_IP_WHITELIST` | 逗号分隔 IP/CIDR | 配置后仅允许命中地址 |
| `LOGIN_POLICY_TIME_WINDOWS` | `HH:MM-HH:MM` | 当前时间落入窗口时拒绝，支持跨午夜 |
| `LOGIN_POLICY_DEVICE_BLACKLIST` | 逗号分隔设备标识 | 匹配 `X-Device-ID` 或 User-Agent |
| `LOGIN_POLICY_DEVICE_WHITELIST` | 逗号分隔设备标识 | 配置后仅允许命中设备 |

登录失败锁定还可通过 `LOGIN_FAILURE_MAX_ATTEMPTS`（默认 `5`）和 `LOGIN_FAILURE_WINDOW_MINUTES`（默认 `15`）调整阈值与窗口。

密码新增、重置和个人修改统一校验长度及四类字符中至少三类。可用以下变量调整规则：

| 变量 | 默认值 | 说明 |
| --- | ---: | --- |
| `PASSWORD_MIN_LENGTH` | `8` | 最小字符数 |
| `PASSWORD_HISTORY_COUNT` | `3` | 历史口令禁止重复的保留数量 |
| `PASSWORD_MAX_AGE_DAYS` | `90` | 口令有效期；登录时超过期限会要求修改 |

## 当前会话

`BaseSessionService` 提供当前会话查看和撤销全部会话接口。当前令牌实现按用户维护一个有效访问令牌，因此“全部会话”与撤销当前用户令牌等价；在底层令牌组件支持多会话索引后再扩展为逐设备撤销。

## 审计日志

Core 将请求和策略事件写入 `base.audit.event`，再由 Core 消费者分别落入 `base_api_log` 和 `base_policy_evaluation_log`；Admin 业务事件写入独立 `admin.audit.event`，由 Admin 消费者落库。六张完整日志模型和自动迁移仍由 Admin 提供，六类日志全部异步入库，队列失败不在请求线程同步写库。普通租户不授予日志菜单和查询权限。

配置完整性密钥并启用任务后，每天 03:30 执行 `system.admin.BaseAuditRetention`，按表把超过保留期的记录写入 JSONL 后删除在线记录：

- `AUDIT_RETENTION_DAYS`：默认 `180`，设置为 `0` 或负数时停用；
- `AUDIT_ARCHIVE_DIR`：默认 `./data/audit-archive`。
- `AUDIT_ARCHIVE_INTEGRITY_KEY`：必填的独立完整性密钥；未配置时归档任务拒绝运行。

归档目录应挂载到受控存储，并由运维侧做加密、校验和备份。归档任务只在文件同步成功后删除在线记录。

## 数据库备份

每天 02:00 执行 `system.admin.BaseBackup`。任务默认关闭，启用时至少设置：

```bash
BACKUP_ENABLED=true
MYSQLDUMP_DATABASE=kratos_admin
MYSQLDUMP_HOST=127.0.0.1
MYSQLDUMP_PORT=3306
MYSQLDUMP_USER=backup
MYSQLDUMP_PASSWORD=***
BACKUP_INTEGRITY_KEY=***
BACKUP_ENCRYPTION_KEY=***
```

`BACKUP_INTEGRITY_KEY` 和 `BACKUP_ENCRYPTION_KEY` 为必填的独立密钥，任务会使用 AES-256 加密备份，并同时写入 SHA-256 和 HMAC 校验文件；恢复脚本会拒绝缺少或校验失败的备份。可选变量：`MYSQLDUMP_BIN`、`OPENSSL_BIN`、`BACKUP_DIR`（默认 `./data/backups`）、`BACKUP_GZIP`（默认 `true`）和 `BACKUP_RETENTION_COUNT`（默认 `7`）。密码通过 `MYSQL_PWD` 传给子进程，不会出现在命令行参数中。恢复前必须停止写入并确认目标数据库，使用仓库内 `scripts/restore_backup.sh` 执行。

OAuth 客户端凭据使用独立的 `OAUTH_CREDENTIAL_ENCRYPTION_KEY` 加密存储，必须由 Secret Manager 注入且长度至少 16 个字符，可用 `OAUTH_CREDENTIAL_ENCRYPTION_KEY_ID` 标识当前密钥版本；JWT 密钥轮换不会复用该密钥。
升级到该策略后，历史明文 OAuth 客户端需通过管理端“轮换客户端凭据”重新生成密钥，系统不再兼容旧明文凭据。

## 对象存储

文件服务复用 Core 的 OSS 适配器，支持 `local`、`aliyun`、`minio` 和 `s3`。单实例开发默认使用 `local`；多实例部署应切换到 MinIO/S3 兼容存储，并为每个租户配置独立路径前缀和最小权限凭据。Compose 中的 MinIO 使用 `object-storage` profile 启动。
