# 安全策略与运维任务

## 登录安全

登录策略按全局、租户、用户作用域保存。每个作用域一条策略，策略下的黑白名单限制按规则逐条保存；只有匹配的启用策略才参与运行时判断，并按用户、租户、全局顺序覆盖失败锁定和密码有效期参数，同时叠加来源限制。没有任何匹配的启用策略时，不执行登录失败锁定、密码有效期和来源限制。

启用策略后，字段 `max_failed_attempts`、`lock_duration_minutes` 和 `password_max_age_days` 分别控制登录失败锁定和密码有效期；`password_max_age_days` 设置为 `0` 时不启用密码有效期。没有启用策略时，这些字段不生效。

MAC 限制匹配客户端提供的 `X-MAC-Address` 请求头，不能在普通 HTTP 中读取真实网卡 MAC；地区限制匹配受信任网关注入的 `X-Region-Code` 请求头，网关必须清理外部伪造值。

密码策略由 `BaseLoginPolicy` 的全局、租户和用户作用域配置，新增、重置和个人修改统一读取当前账号生效策略。密码复杂度按小写、大写、数字、符号四类字符计算。

密码策略字段如下：

| 字段 | 默认值 | 说明 |
| --- | ---: | --- |
| `password_min_length` | `8` | 最小字符数 |
| `password_history_count` | `3` | 历史密码禁止重复的保留数量，`0` 表示不启用 |
| `password_min_complexity_classes` | `3` | 至少满足的小写、大写、数字、符号类别数量 |
| `password_max_age_days` | `90` | 密码有效期，`0` 表示不启用 |
| `initial_password` | 未配置 | 新增用户未提交密码时使用；该用户首次登录必须修改密码 |

## 当前会话

`BaseSessionService` 提供当前会话查看和撤销全部会话接口。登录时服务端记录会话创建时间、令牌签发时间、来源地址、设备和最后业务活动时间；管理 API 请求更新活动时间，刷新令牌请求不延长空闲时间。默认空闲超时为 30 分钟、绝对生命周期为 12 小时，由 `authn.session` 配置。

## 审计日志

Core 将请求和策略事件写入 `Core 日志事件流`，再由 Core 消费者分别落入 `base_api_log` 和 `base_policy_evaluation_log`；Admin 业务事件写入独立 `admin.log.event`，由 Admin 消费者落库。六张完整日志模型和自动迁移仍由 Admin 提供，六类日志全部异步入库，队列失败不在请求线程同步写库。普通租户不授予日志菜单和查询权限。

Admin 审计缓冲关闭/满、队列不可用或投递失败时，会根据隐藏系统配置 `auditLogSpool.file_path` 写入固定文件名 `admin-log.jsonl`，并执行文件同步；每条记录使用运行时密钥服务按 `kratos-admin:audit-log-spool/integrity` 派生密钥生成 HMAC。日志入库回退文件由 `system.admin.BaseLogFallback` 任务每日重新写入日志表，并应配置独立审计存储和告警。数据访问日志从真实 Proto 响应提取返回字段范围、记录条数和敏感字段触达标识；没有数据层事实时不伪造 SQL、表名或 SQL 指纹。

日志入库回退参数保存在隐藏系统配置 `auditLogSpool` 中，由系统配置服务统一维护并实时刷新缓存。配置结构如下：

```json
{
  "file_path": "./data/audit-log-spool"
}
```

启用定时任务 `system.admin.BaseTableArchive` 后，每天 03:30 读取 `base_table_archive` 中启用的表归档配置，按表将超过在线保留期的数据归档到当前数据源归档表或 OSS；只有归档校验成功且配置允许时才删除在线记录。普通应用日志的文件轮转和压缩由 `kratos-kit/logger` 负责。

## 数据库备份

数据库备份策略保存在 `base_table_backup` 中，数据库连接复用启动配置中的 `data.database` 或 `data.databases`；启用状态和保留数量均按数据源记录维护。每天 02:00 执行 `system.admin.BaseTableBackup`，备份完整性密钥和加密密钥分别按 `kratos-admin:backup/integrity`、`kratos-admin:backup/encryption` 从运行时密钥服务派生，不再通过服务进程环境变量注入：

`base_table_backup.status` 控制是否执行，`base_table_backup.retention_count` 控制保留数量；备份统一压缩、加密并上传 OSS。

任务会使用 AES-256 加密备份并上传 OSS，同时将 SHA-256、HMAC 和对象信息写入 `base_table_backup_record`；任务会回读 OSS 对象校验后才标记成功，恢复流程会拒绝缺少或校验失败的备份。备份和恢复均由服务程序控制，密钥不会通过服务进程环境变量注入，也不会出现在命令行参数中。

恢复统一通过管理端 `BaseTableBackupRestoreService.ExecuteBaseTableBackupRestore` 执行。程序会从 OSS 下载已校验的备份对象，完成完整性校验、解密、解压和导入；恢复前仍必须停止业务写入，并使用隔离环境完成恢复演练。

OAuth 客户端凭据使用独立的 `kratos-admin:oauth/credential-protection` 派生密钥加密存储；JWT 密钥轮换不会复用该密钥。
升级到该策略后，历史明文 OAuth 客户端需通过管理端“轮换客户端凭据”重新生成密钥，系统不再兼容旧明文凭据。

## 对象存储

文件服务复用 Core 的 OSS 适配器，支持 `local`、`aliyun`、`minio` 和 `s3`。单实例开发默认使用 `local`；多实例部署应切换到 MinIO/S3 兼容存储，并为每个租户配置独立路径前缀和最小权限凭据。Compose 中的 MinIO 使用 `object-storage` profile 启动。

上传入口限制文件数量、大小和扩展名，校验扩展名与服务端嗅探 MIME 一致，并拒绝 HTML、SVG、PHP、Flash 等可执行或可嵌入类型。生产环境可通过 `oss.upload_security` 配置 ClamAV 兼容扫描命令；若文件先进入外部隔离区并由网关扫描，可声明 `SECURITY_EXTERNAL_FILE_SCAN=true`，同时保留隔离、扫描结果和放行日志。

## 生产安全校验

独立服务以 `prod` 或 `production` 启动时会在数据库初始化前校验安全基线。外部能力声明包括：

| 变量 | 外部能力与必要证据 |
| --- | --- |
| `SECURITY_TLS_TERMINATED` | 反向代理或负载均衡 TLS 配置、证书和协议扫描结果 |
| `SECURITY_DATABASE_TLS_TERMINATED` | 数据库代理或服务网格链路加密配置 |
| `SECURITY_REDIS_TLS_TERMINATED` | Redis 代理或服务网格链路加密配置 |
| `SECURITY_EXTERNAL_BACKUP` | 备份策略、异地副本、恢复演练和 RPO/RTO 记录 |
| `SECURITY_EXTERNAL_LOG_ARCHIVE` | SIEM/WORM 留存策略、访问控制和完整性证据 |
| `SECURITY_EXTERNAL_FILE_SCAN` | 隔离区、恶意代码扫描策略和放行日志 |

未由外部平台承担时，应在 `base_table_archive`、`base_table_backup` 中配置归档与备份策略，在隐藏配置 `auditLogSpool` 中配置日志入库回退，并在 `oss.upload_security` 中配置扫描命令。生产校验只防止明显错误配置，不能替代等保测评、渗透测试和运维制度。

普通 HTTP API 默认请求体上限为 64 MiB、处理超时为 30 秒，统一由 `server.http.max_body_bytes` 和 `server.http.timeout` 配置。`/events`、`/mcp` 和 AI 消息流默认不设置请求超时，仅由 HTTP 请求体上限保护；文件上传还有独立的 20 MiB 单文件和 20 文件限制。
