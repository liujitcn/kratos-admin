# BI 与智能问数设计

当前闭环为：数据源 → 问数与查询记录 → 数据卡片 → 仪表盘组合 → 发布 → 工作台或业务菜单。

## 菜单与页面

BI 分析为一级菜单 `91000000`，与 AI 助手 `90000000` 同级并排在其后；系统管理为 `97000000`，Demo 演示为 `98000000`。BI 页面按 `91010000` 至 `91070000` 编号，数据源操作按钮为 `91050100` 至 `91050400`。

| 菜单 | 页面职责 |
| --- | --- |
| 我的工作台 | 展示收藏的已发布仪表盘入口，默认拖动排序并自动保存，通过页面刷新取数 |
| 智能问数 | 左侧历史记录、中间提问和结果说明、右侧真实结果卡片预览 |
| 数据卡片库 | 查询和图表配置的统一资产，支持收藏、项目内共享及加入仪表盘 |
| 仪表盘管理 | 创建草稿、组装卡片、保存、发布、收藏或取消收藏及配置业务菜单 |
| 数据源管理 | 沿用连接配置、表结构发现、关联画布和语义字段建模 |

“设计器”和“仪表盘查看”是隐藏路由；问数记录不再有独立侧栏页面。工作台只提供仪表盘入口，不再组合原始数据卡片。

工作台不提供顶部条件或操作栏，默认可拖动排序，松开后自动保存，失败恢复原顺序；聚焦入口后也可用 Alt+左右方向键排序。仪表盘管理在“状态”列前通过“收藏”开关控制入口增减，复用状态列组件，保存成功后切换，新收藏追加到末尾，独立卡片收藏不受影响。首次未配置工作台时为空，不自动加入已发布仪表盘；已有个人配置继续保留。

问数历史复用 System 的 `AiSessionPanel`，输入区复用相同的模型选择器与语音能力。Enter 发送、Shift+Enter 换行，输入法选字不提交；离开页面停止语音识别。

## 数据模型

| 表 | 保存内容 |
| --- | --- |
| `bi_source` | 数据库连接与受控语义模型 |
| `bi_query` | 查询计划、租户/项目/用户、执行状态和完整类型化结果快照 |
| `bi_card` | 来源成功查询记录 ID、查询定义、图表类型、字段映射、样式、刷新和共享配置 |
| `bi_dashboard` | 仪表盘名称、项目、所有者和当前草稿/发布版本 |
| `bi_dashboard_version` | 卡片引用与布局的草稿，以及由服务端生成的独立发布快照 |
| `bi_workbench` | 当前用户的仪表盘入口顺序和独立的数据卡片收藏 |

模型由开发库结构通过 `make -C backend gorm-gen` 生成，启动时由 GORM AutoMigrate 创建。生成链路保留结果快照的大文本容量，避免启动时将 `MEDIUMTEXT` 缩小为 `TEXT`。初始化脚本只维护默认数据、菜单和权限，不再在 `default_data.up.sql` 重复建表。

卡片必须引用当前账号、当前项目下成功的智能问数记录；记录必须有真实提问，请求中的查询与该记录必须一致。手动预览、卡片刷新、仪表盘执行记录均不能作为新卡片来源。修改查询条件需要重新智能问数；卡片编辑只调整展示配置，不允许拼接并未执行的来源。查询记录详情仅返回当前用户有权读取的快照。

卡片支持现有 13 类图表，另保留指标卡。统一编辑器配置维度、数值、第二分类/流向字段，以及图例、标签、堆叠和缩放。图表类型根据实际查询结果结构启用：散点图需要两个数值字段；桑基、热力、旭日需要两个分类字段和一个数值字段。服务端只接受结果中存在的字段及受控展示配置，不接受任意 ECharts 选项或客户端数据源代码。

`chart_json` 保存 `encoding` 和 `style`，图型由 `chart_type` 唯一标识，避免在 JSON 再保存一份类型。业务数据值不保存在卡片中，卡片关联的来源记录可供追溯，打开或刷新卡片时按访问者权限重新执行查询。

## 仪表盘布局与发布

当前仪表盘布局版本为 3：

```json
{
  "schemaVersion": 3,
  "name": "用户分析总览",
  "theme": { "key": "auto" },
  "cards": [
    { "id": "card_1", "card_id": 1, "x": 0, "y": 0, "w": 6, "h": 4 }
  ]
}
```

草稿只保存卡片引用和 12 列栅格布局，允许先创建空草稿。仪表盘名称和说明在管理列表编辑；设计器采用卡片库与画布两栏，提供卡片选择、排序和卡片内的宽高设置，外观自动跟随管理端明暗模式。需要编辑图表时打开同一个卡片表单。

保存和发布校验卡片的租户、项目、可见性与布局边界；最多 20 张卡片。发布时服务端再次验证智能问数来源，并从卡片仓储补齐名称、图表配置、原始问数记录 ID 和查询定义，不信任客户端上传的快照。卡片后续修改或删除不改写历史发布配置，重新发布才采用最新配置；业务数据值仍通过当前访问者的可信范围查询。

草稿只允许所有者修改。保存和发布均原子校验草稿版本，同一版本只能固定一次发布快照；并发变更返回冲突。已发布页面供具有对应接口/菜单权限且处于同一租户、项目范围的用户查看。旧的未接入页面的 `bi_dashboard_share` 表和独立共享逻辑已移除。发布不扩大底层查询的数据权限。

## 接口与路由

- `/api/v1/admin/bi/query/ask` 与 `/query/preview` 返回统一的列、类型、行以及 `query_record_id`。
- `/api/v1/admin/bi/query-record` 提供当前用户的问数历史；记录详情包含完整类型化结果。手动预览、卡片刷新和仪表盘执行仍留痕，但不进入自然语言历史列表。
- `/api/v1/admin/bi/card` 保存查询关联与展示配置，`/{id}/data` 执行真实取数。
- `/api/v1/admin/bi/dashboard` 保存卡片引用与布局，`/{id}/publish` 固定发布快照，`/{id}/data` 返回快照和卡片结果。
- `/api/v1/admin/bi/workbench` 保存 `dashboard_ids` 和 `favorite_ids`，返回当前可访问的已发布仪表盘入口。

工作台与管理列表进入 `/bi/dashboard/:id`，共用一个展示页面。仪表盘管理页提供独立的菜单配置表单，只填写菜单标题、图标和放置目录；路径固定为 `/reports/dashboard/{id}`，名称固定为 `BiDashboard{id}`，组件、权限及页面选项自动设置，不填写路由参数。通用菜单管理表单不承载 BI 专用逻辑。展示页从地址路径读取编号，切换仪表盘时重新加载并丢弃迟到响应。

## 初始化与验证

不提供旧版本布局或旧工作台数据兼容层。需使用全新数据库初始化验证；修改 `v0.0.1` 不会让已经执行过的数据库自动重放菜单、角色和语言种子。

新模型不再创建旧共享表；存量表不会由 AutoMigrate 自动删除。开发环境重建时先备份现有数据库，再创建空库并启动当前服务，统一执行建表和 `v0.0.1` 初始化。

```bash
make -C backend gen
make -C frontend ts-admin
make i18n I18N_MIGRATION_VERSION=v0.0.1
make menu-sort
go -C backend test ./...
pnpm -C frontend/admin type:check
pnpm -C frontend/admin lint:oxlint
pnpm -C frontend/admin --filter @liujitcn/kratos-admin-bi test
```

查询继续复用 `SourceAdapter` 和语义模型。模型不得输出 SQL，不允许从卡片或仪表盘绕过租户、项目、字段与查询限制。AI 对话工具与 BI 页面共用同一个受控查询执行内核。

可配置数据源当前只声明租户隔离字段，不能承担项目隔离。持有单项目授权的请求会明确拒绝执行可配置源，避免按整租户取数；需要项目数据时使用已实现项目权限的宿主 `SourceAdapter`。

宿主数据库客户端只允许默认租户配置和使用。普通租户必须提供独立连接凭据；创建、更新、测试、发现表结构、保存模型和实际执行都执行此边界，已有配置不能绕过。独立连接中的共享表或连接级隔离可不填写租户字段；共享宿主库不向普通租户开放自定义表和隔离规则。
