# 缓存键命名约定

本文约定本仓库业务代码使用的缓存键和分布式锁键。缓存使用 Redis 或内存实现，不改变业务键的命名规则。

## 命名格式

```text
{端侧}:{业务域}:{资源}[:{标识}...]
```

键名统一使用小写英文和冒号分段。资源和标识按稳定顺序排列；TTL 由代码设置，不写入键名。

| 前缀 | 使用范围 | 示例 |
| --- | --- | --- |
| `admin:` | 仅管理端读取或使用的状态 | `admin:config:site:2` |
| `app:` | uni-app、Taro 等应用端读取或使用的状态 | `app:dict:data:4:status` |
| `shared:` | 管理端和应用端确实共用的业务数据，或两端共同使用的 Base 认证能力 | `shared:notification:categories:4`、`shared:auth:session:index` |

前缀按数据消费者确定，不按写入方或 Redis 部署方式确定。多个服务节点共用 Redis，不代表键应该使用 `shared:`；只有业务数据本身跨端共用才使用该前缀。Base 登录、MFA、会话和登录策略接口由管理端与应用端共同使用，因此放入 `shared:auth:`。管理端修改应用端数据时，仍更新 `app:` 缓存对应的版本键。

## 当前键空间

| 键模式 | 用途 |
| --- | --- |
| `admin:config:site:{site}`、`admin:config:hidden:{key}` | 管理端配置快照和敏感运行配置 |
| `admin:auth:phone:update:code:{userID}:{phoneHash}`、`admin:oauth:login:ticket:{ticketHash}` | 管理端手机号验证和 OAuth 一次性票据 |
| `app:auth:wx:access-token`、`app:area:tree` | 应用端微信令牌和行政区域树 |
| `app:config:site:{site}`、`app:dict:*`、`app:menu:*` | 应用端配置、字典和菜单快照 |
| `shared:auth:*` | 两端共用的登录安全状态、MFA、会话及口令策略 |
| `shared:oauth:client:failure:*` | 跨端共用的 OAuth 客户端失败计数 |
| `shared:notification:*` | 两端共用的通知分类数据 |

需要按用户输入或一次性凭证区分缓存项时，键只包含其 SHA-256 摘要，不包含手机号、验证码、挑战 ID 或票据原文。

## 版本化缓存

适合整体快照的缓存使用独立版本键和带版本的数据键：

```text
app:dict:revision
app:dict:data:{revision}:{code}
app:menu:revision
app:menu:tree:{revision}
```

写入方在数据库事务成功后原子递增版本键。所有节点读取同一个共享版本，因此后续读取会转向新版本的数据键；旧数据键由 TTL 回收。版本键本身不设 TTL，避免版本回退后重新命中旧数据。

公共读写方法位于 `github.com/liujitcn/kratos-kit/cache`：`ReadRevision` 读取版本，`IncrementRevision` 原子递增版本。业务侧负责决定哪些数据变更需要递增，以及缓存异常时的业务处理。

## 标识与敏感数据

- 标识使用稳定 ID；多租户数据需要包含足以隔离租户的维度。
- 不把密码、验证码、访问令牌、刷新令牌、手机号等原文拼进键名。确需按其区分缓存项时，先用 SHA-256 摘要，再将摘要放入键名。
- 动态值不得直接携带冒号等分隔符；复杂值应规范编码或摘要，保证不同参数组合不会产生歧义。
- 新键应由常量或键构造函数生成，不在多个读写点分别拼接同一格式。

## 兼容与边界

键名变更后只读写新键，不回退读取旧键。普通缓存旧值等待 TTL 过期；认证和会话类状态切换后可能要求用户重新登录。变更时同步更新所有读写调用、常量、测试和本约定。

本约定管理本仓库显式定义的业务键。`kratos-core`、`kratos-kit` 等依赖内部生成的键由对应组件维护；需要改变时应在依赖组件中调整并同步更新本仓库依赖，不在业务代码旁路重建或兼容其旧键。密码/MFA/OAuth 加密、脱敏和备份密钥提供器使用的逻辑密钥名称不是缓存键，不适用本约定。
