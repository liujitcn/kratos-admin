# 数据库与初始化数据

## 当前数据源

系统默认使用 MySQL 数据库 `kratos_admin`，基础配置位于 `backend/configs/data.yaml`，开发环境差异位于 `backend/configs/data.dev.yaml`。Redis 用于验证码、一次性密码密钥、Token 等缓存状态。

`data.database` 表示单一默认数据源；`data.databases` 可声明多个命名数据源。默认数据源保存系统表以及所有模块的 `base_migration` 执行记录。

## 建表和迁移

启动顺序为：

1. 创建全部 GORM 客户端。
2. 对 `enable_migrate: true` 的客户端执行注册模型的 `AutoMigrate`。
3. 加载模块迁移资源，按依赖、版本、数据库类型和数据源执行 `.up.sql`。
4. 将迁移目录中的现有多语言说明同步到统一翻译表。
5. 完成 OpenAPI 接口数据、租户角色菜单和 Casbin 策略同步。

`enable_migrate` 只控制 GORM 自动建表，不会关闭 `v0.0.1` 初始化 SQL。全新环境应为默认数据源启用它，否则 `base_migration` 等表可能尚不存在。

## 资源结构

基础初始化资源目录：

```text
backend/migration/assets/v0.0.1/mysql/
├── README.md
├── README.en-US.md
├── README.ja-JP.md
├── README.zh-TW.md
├── base_area.up.sql
├── default_data.up.sql
├── i18n.en-US.up.sql
├── i18n.zh-TW.up.sql
└── i18n.ja-JP.up.sql
```

MFA 认证方式拆分使用 GORM 自动迁移创建 `base_user_mfa`、`base_user_mfa_totp`、`base_user_mfa_webauthn` 和 `base_user_mfa_recovery` 表；开放授权客户端使用 GORM 自动迁移创建 `oauth_client` 表。默认 MFA 策略、认证方式、开放授权菜单/API 和管理员权限直接写入 `v0.0.1` 的初始化脚本。

本仓库的初始化迁移固定使用 `v0.0.1`，目录规则如下：

```text
assets/v0.0.1/<database-type>/<feature>.up.sql
assets/v0.0.1/<database-type>/README.md
assets/v0.0.1/<database-type>/README.<locale>.md              # 可选
assets/v0.0.1/<database-type>/<data-source>/<feature>.up.sql
assets/v0.0.1/<database-type>/<data-source>/README.md
assets/v0.0.1/<database-type>/<data-source>/README.<locale>.md # 可选
```

当前仓库内置并验证的是 `mysql`。数据库类型目录下的直系文件属于 `default` 数据源；一级子目录是命名数据源，必须与配置名称一致。脚本按文件名排序执行，`base_migration.description` 只读取同目录的 `README.md`。如需接入其他数据库类型，仍须在 `v0.0.1` 下增加对应数据库类型目录，不得新增版本目录。

`README.<locale>.md` 以 `base_migration.id` 为目标 ID、以 `I18N_TARGET_TYPE_BASE_MIGRATION_DESCRIPTION` 为目标类型同步到 `base_i18n`。语言文件存在时以文件内容更新对应译文；不存在时不新增、不修改该语言记录。详情接口优先返回请求语言的译文，缺失时回退 `base_migration.description`。

迁移记录唯一标识包含模块、数据源和版本。一个版本内任一升级脚本失败会回滚该版本并阻止服务启动，修复后重启会重试未记录版本。

## 初始化内容

`default_data.up.sql` 与同版本语言脚本共同提供：

- 默认租户、部门、岗位、角色和 `super`、`admin` 开发账号。
- 系统配置、字典、菜单、按钮和服务方法权限关系。
- 管理端 System 页面、AI、代码生成、API 文档和应用端所需权限入口。
- MFA 策略与认证方式字典，以及开放授权客户端管理菜单和 API 选项权限。

`default_data.up.sql` 负责语言记录、默认业务数据、菜单和权限；同版本 `i18n.{locale}.up.sql` 通过 `base_i18n.target_type` 提供菜单、字典、字典项、系统配置名称/值和定时任务名称的非主语言译文。Core 在迁移执行完成后将 `README.<locale>.md` 写入 `base_i18n`，Admin 详情接口直接查询该表。主语言由 `base_language.is_primary` 配置，主表保存主语言文本，其他启用语言保存到统一翻译表。翻译表及代码生成 `i18n_config` 字段由 GORM `AutoMigrate` 创建。

`base_area.up.sql` 提供地区基础数据。初始化 SQL 使用 `INSERT IGNORE`，遇到已有唯一键记录时跳过，不覆盖已有数据。

启动时 `BaseApiCase.InitializeOpenAPI` 根据已注册 OpenAPI 重建接口元数据，随后同步租户管理员菜单并重建 Casbin 规则。因此修改 Proto 路径或菜单 API 列表时，必须同时重新生成 OpenAPI 并更新 `v0.0.1` 初始化 SQL。

## 初始化变更

- 所有新功能需要的表结构配套初始化数据、默认数据、菜单、接口权限和翻译，统一补齐到 `v0.0.1` 的完整初始化状态。
- 直接修改 `backend/migration/assets/v0.0.1/mysql` 下对应脚本和说明；不新增 `v0.0.2` 或更高版本，也不增加面向存量库的增量 `.up.sql`/`.down.sql`。
- 新增语言按[国际化语言扩展指南](国际化语言扩展指南.md)生成语言包，并将初始化 SQL 写入 `v0.0.1`；动态固定译文仍使用 `i18n.<locale>.up.sql`。
- SQL 保持幂等，避免 `TRUNCATE`、无条件全表更新或删除。
- 已记录 `v0.0.1` 的数据库不会因初始化脚本被修改而自动重放；验证初始化内容时使用全新数据库或按开发环境流程重建。
