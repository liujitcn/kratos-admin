# 模块设计方案

本文只保留当前仓库已经采用的模块边界和装配方式。新增模块的操作步骤见
[服务接入指南](服务接入指南.md)。

## 当前模块

```text
backend/api/proto
        │
        ├── api/gen/go                  # Go 生成协议
        ├── frontend/admin/src/rpc      # 管理端生成类型
        └── frontend/app/src/rpc        # 应用端生成类型
                │
backend/service/{base,system}
                │
backend/server/{base,system}
                │
backend/app.go + backend/internal/cmd/server/wire.go
```

| 目录 | 当前职责 | 不承担 |
| --- | --- | --- |
| `backend/api/proto` | 对外接口和参数校验契约。 | 业务实现和数据库查询。 |
| `backend/pkg` | 配置、认证、权限、任务、事件、生成数据访问和基础设施。 | 具体业务流程。 |
| `backend/service/base` | 登录、文件、SSE、AI、MCP 等公共能力。 | 依赖某个具体业务模块。 |
| `backend/service/system` | 用户、租户、组织、权限、代码生成等系统能力。 | 前端页面编排。 |
| `backend/server` | HTTP、gRPC、MCP 服务注册和传输适配。 | 领域规则和持久化逻辑。 |
| `backend/app.go` | 汇总 ProviderSet、创建模块列表和 Kratos App。 | 具体业务用例。 |
| `frontend/admin/src` | 管理后台页面、请求封装和生成类型。 | 手写重复的接口类型。 |
| `frontend/app/src` | 应用壳子页面、请求封装和状态。 | 管理后台页面和后台权限模型。 |

## 模块装配

后端模块通过 `server.Module` 接口挂载：

```go
type Module interface {
    RegisterGRPC(*grpc.Server)
    RegisterHTTP(*http.Server)
    RegisterMCP(*mcpserver.Server)
}
```

`backend/app.go` 的 `ProviderSet` 提供基础模块和系统模块，`NewModules` 按顺序汇总
`base`、`system.admin`、`system.app` 以及 `AdditionalModules`。当前组合根在
`backend/internal/cmd/server/wire.go` 中通过 Wire 显式提供依赖。

新增模块必须同时提供业务层和传输层 `ProviderSet`，在 `backend/app.go` 加入依赖，并在
`NewModules` 或 `AdditionalModules` 中加入模块实例。模块是否启用应能从组合根的 import、
ProviderSet 和构造参数直接看出，禁止依赖 `init()`、反射或运行时扫描。

### 依赖方向

```text
api/proto
  ↓
service/*/biz  →  pkg/gen、pkg 基础能力
  ↓
service/*_service.go
  ↓
server/*/register.go
  ↓
app.go / wire.go
```

基础模块不能反向依赖业务模块。业务模块可以依赖稳定的 `pkg`、`base` 和 `system` 能力；
模块之间需要协作时，通过组合根装配适配器，或者使用不含业务语义的事件接口。

## 前后端对应关系

| 后端契约 | 管理后台 | 应用端 |
| --- | --- | --- |
| `base.v1` | `src/api/base` | `src/api/base` |
| `system.admin.v1` | `src/api/system`、`src/views/system` | 不生成 |
| `system.app.v1` | 不生成 | `src/api/system`、应用页面 |

接口路径、菜单组件和权限数据是同一功能的一部分。管理后台页面的 `component` 必须能够被
已注册的视图模块解析，按钮权限必须写入对应版本迁移。

## 生成与验证

```bash
cd backend
make api openapi ts ts-app
make wire
go test ./...

cd ../frontend/admin
pnpm type:check
pnpm lint:oxlint

cd ../app
pnpm tsc
pnpm lint
```

`api/gen/go`、`pkg/gen`、OpenAPI、`frontend/admin/src/rpc` 和 `frontend/app/src/rpc` 均为
生成产物。变更接口或数据库后，必须使用对应命令重新生成，不能直接修改生成文件。
