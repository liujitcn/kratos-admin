# 模块设计方案

本文只保留当前仓库已经采用的模块边界和装配方式。新增模块的操作步骤见
[服务接入指南](服务接入指南.md)。

## 当前模块

```text
backend/api/proto
        │
        ├── api/gen/go                  # Go 生成协议
        ├── frontend/admin/src/rpc      # 管理端生成类型
        └── frontend/app/src/rpc        # 应用端生成类型
                │
backend/internal/service/{base,admin,app}
                │
backend/internal/server/{base,admin,app}
                │
backend/app.go + backend/wire.go
```

| 目录 | 当前职责 | 不承担 |
| --- | --- | --- |
| `backend/api/proto` | 对外接口和参数校验契约。 | 业务实现和数据库查询。 |
| `backend/internal/biz` | Case、业务规则和内部基础能力。 | 对其他 Go module 暴露实现类型。 |
| `backend/internal/data/gen` | GORM Model、Query 和 Repository。 | 作为跨模块数据接口。 |
| `backend/internal/service` | Proto 服务实现。 | 供调用方直接构造或依赖。 |
| `backend/internal/server` | HTTP、gRPC、MCP 服务注册和传输适配。 | 领域规则和持久化逻辑。 |
| `backend/app.go` | 暴露 `NewModule`、本地 ClientConn 和独立应用入口。 | 暴露内部 ProviderSet。 |
| `backend/core/pkg/errorsx` | 稳定的公共业务错误构造与数据库错误识别能力。 | 数据库访问或业务实现。 |
| `frontend/admin/src` | 管理后台页面、请求封装和生成类型。 | 手写重复的接口类型。 |
| `frontend/app/src` | 应用壳子页面、请求封装和状态。 | 管理后台页面和后台权限模型。 |

## 模块装配

后端服务组通过 `core.Module` 接口挂载：

```go
type Module interface {
    RegisterGRPC(grpc.ServiceRegistrar)
    RegisterHTTP(*http.Server)
    RegisterMCP(*mcpserver.Server)
}
```

根包返回的 `kratosadmin.Runtime` 在该接口上额外提供 `ClientConn() grpc.ClientConnInterface`，
供同进程调用方创建生成的 gRPC Client。

`kratosadmin.NewModule` 在 Backend 内部通过 Wire 装配 `base`、`system.admin`、`system.app`
及调用方传入的 `AdditionalModules`，返回可注册的 `Runtime`。外部启动器不会展开内部
ProviderSet，也不能导入 `internal` 实现。`kratosadmin.NewApp` 复用同一 Runtime，再创建独立
HTTP、gRPC Server。

新增内置模块必须同时提供业务层和传输层 ProviderSet，在 `moduleProviderSet` 加入依赖，并在
`newModules` 中加入模块实例。外部模块通过 `WithAdditionalModules` 传入。模块是否启用应能从
组合根的 import、ProviderSet 和构造参数直接看出，禁止依赖 `init()`、反射或运行时扫描。

### 依赖方向

```text
api/proto
  ↓
internal/biz  →  internal/data/gen、内部基础能力
  ↓
internal/service/*_service.go
  ↓
internal/server/*/register.go
  ↓
app.go / wire_gen.go
```

跨模块读取 Backend 数据时必须依赖 `api/gen/go` 中的生成 gRPC Client。远程部署给客户端注入
标准 gRPC 连接；同进程部署给相同客户端注入 `Runtime.ClientConn()`。禁止通过公开 Repo、Model、
Query 或 Case 绕过服务契约。

## 前后端对应关系

| 后端契约 | 管理后台 | 应用端 |
| --- | --- | --- |
| `base.v1` | `src/api/base` | `src/api/base` |
| `system.admin.v1` | `src/api/system`、`src/views/system` | 不生成 |
| `system.app.v1` | 不生成 | `src/api/system`、应用页面 |

接口路径、菜单组件和权限数据是同一功能的一部分。管理后台页面的 `component` 必须能够被
已注册的视图模块解析，按钮权限必须写入对应版本迁移。

## 生成与验证

```bash
cd backend
make api openapi ts ts-app
make wire
go test ./...

cd ../frontend/admin
pnpm type:check
pnpm lint:oxlint

cd ../app
pnpm tsc
pnpm lint
```

`api/gen/go`、`internal/data/gen`、OpenAPI、`frontend/admin/src/rpc` 和 `frontend/app/src/rpc` 均为
生成产物。变更接口或数据库后，必须使用对应命令重新生成，不能直接修改生成文件。
