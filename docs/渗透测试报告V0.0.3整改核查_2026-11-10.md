## 三、关键问题与处理建议

### 1. cloud-scp 必须先升级依赖，否则复测仍不通过

- 越权修复新增的 `ResolveContext` 只有 kratos-core ≥ v0.0.56 才会调用；v0.0.52 只认 `ResolveTenant`，不升级则修复不生效。
- SSRF 修复依赖 `kratos-kit/transport/safehttp`（≥ v0.0.30），下游锁定 v0.0.28，当前 `go build ./...` 失败。
- `project_sync.go`、`project_cluster_service.go`、`module.go` 三个文件 gofmt 不通过。
- 前端包需从 `^0.1.5` 升级到 0.1.12+，协议勾选与版本展示依赖新包。
- 升级后需配置 `SECURITY_CLUSTER_ALLOWED_HOSTS/CIDRS`，出站策略默认全拒，不配置则集群连接全部被拒。

### 2. 高危项（5.1）是沙箱兜底方案，非报告建议的引擎级禁用

现状：`runtime.go:133/135` 仍显式开放 Lua 的 `os/io/load` 库与 TCL 的 `exec` 命令；`base_script.go:171` 仍接受内联草稿源码。补偿控制为操作系统级沙箱（macOS sandbox-exec / Linux bubblewrap）+ 命令白名单 + 受控出站代理。

实测（macOS）：报告 PoC 全部被拦截——`io.popen` 报 `fork/exec /bin/sh: operation not permitted`，未授权文件 `operation not permitted`，环境变量清空，`debug` 库为 nil。

注意事项：

- Linux（bubblewrap 分支）仅经代码审查确认，未实测。
- 容器必须允许用户命名空间，否则脚本功能直接报错不可用（不回退到不安全执行）。
- 仓库内**没有命令执行被拦截的回归测试**，现有测试只覆盖文件与 HTTP。
- 是否接受替代方案需与测试组确认。

### 3. 工作区未提交改动引入协议确认登录回归

`config.go:75` 改为管理端只查本站点协议，但 `log.go:258` 的 `validateAgreement` 仍借用移动端协议（sites 2,3）。存量库无管理端协议行 1161/1162 时两端摘要不一致，勾选后登录被拒（提示"协议内容已更新，请刷新并重新确认"）。

- 迁移 README 已写明需手工补录 1161/1162 及四语言译文；测试环境为存量库，升级时必遇。
- 建议将中间件改为与 `GetConfig` 一致的按站点取值。
- 该结论来自代码走读，未起服务验证。
