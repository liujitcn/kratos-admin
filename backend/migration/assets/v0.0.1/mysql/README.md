# MySQL 默认初始化资源

本目录维护 `v0.0.1` 的 MySQL 初始化资源。脚本只写入默认数据，不包含建表语句；服务启动时由 GORM `AutoMigrate` 创建启用迁移的模型，再按文件名执行同目录的 `.up.sql`。

## 文件职责

| 文件 | 内容 |
| --- | --- |
| `default_data.up.sql` | 默认语言、配置、部门、字典、字典项、任务、租户、消息分类、菜单、角色、脱敏规则、脱敏字段、脱敏策略和开发账号。 |
| `base_area.up.sql` | 行政区划基础数据，作为独立脚本参与默认数据源迁移。 |
| `i18n.en-US.up.sql` | `en-US` 的 `base_i18n` 翻译数据。 |
| `i18n.ja-JP.up.sql` | `ja-JP` 的 `base_i18n` 翻译数据。 |
| `i18n.zh-TW.up.sql` | `zh-TW` 的 `base_i18n` 翻译数据。 |
| `README.<locale>.md` | 迁移说明的对应语言版本，由迁移框架同步到统一翻译表。 |

## 执行与幂等

启动时依次执行自动建表、SQL 迁移、迁移说明翻译同步，以及 OpenAPI、`base_api`、租户菜单和 Casbin 策略同步。`default_data.up.sql` 和 `base_area.up.sql` 会临时关闭外键检查，脚本结束时恢复原值。

所有初始化记录均使用单行 `INSERT IGNORE`：已有唯一键记录会跳过，不覆盖业务数据；脚本不使用批量 `INSERT`、`UPDATE`、`DELETE` 或 `TRUNCATE`。`default_data.up.sql` 中同一表内的记录按 `id` 升序维护，新增默认数据应放在对应的编号位置。

已记录过 `v0.0.1` 的数据库不会因为修改初始化文件而自动重放。验证修改时请使用全新数据库，或按开发环境流程重建数据库。新增功能仍应补齐 `v0.0.1` 的完整初始化状态，不新增更高版本或面向存量库的增量脚本。

## 默认数据

`default_data.up.sql` 当前写入以下默认数据表：

`base_language`、`base_config`、`base_dept`、`base_dict`、`base_dict_item`、`base_job`、`base_tenant`、`base_message_category`、`base_menu`、`base_role`、`base_user`、`base_redact_rule`、`base_redact_storage_policy`、`base_redact_output_policy`。

- 语言：预置 `zh-CN`、`zh-TW`、`en-US`、`ja-JP`，其中 `zh-CN` 为主语言。
- 登录租户编号：管理端（`site=2`）和应用端（`site=3`）均预置布尔配置 `showTenantCode=true`，默认显示租户编号输入框；配置名称包含英文、繁体中文和日文翻译。
- 基础身份：预置默认租户、系统管理部门、5 个角色模板，以及 `super`、`admin` 两个本地开发账号。账号初始密码为 `112233`，仅用于本地环境。
- 配置与字典：包含管理端和应用端配置、验证码、OAuth 自动注册、租户编号显示、多因素认证策略和认证方式；日志入库回退使用隐藏系统配置 `baseLogFallback`，日志保留策略写入 `base_table_archive`，数据库备份策略写入 `base_table_backup`，会话生命周期和上传扫描由 `authn.session`、`oss.upload_security` 配置；持久化字典覆盖菜单、审计、登录策略、消息、权限和代码生成等枚举。
- 任务与消息：任务编号 `1000-1004` 分别用于资源翻译、消息投递恢复、数据表归档、数据表备份和日志入库回退；消息投递恢复与日志入库回退默认启用，归档和备份默认关闭。归档配置保存在 `base_table_archive`，备份配置保存在 `base_table_backup`。消息分类预置系统、安全、任务、业务四类。
- 菜单与权限：预置首页、租户管理、用户管理、系统管理四个管理端根菜单，以及移动端根菜单 `99000000`。系统管理下按优先级设置基础管理、权限管理、登录管理、消息通知、数据脱敏、数据备份、数据归档、日志审计、定时任务、系统运维、开发工具 11 个二级目录，编号为 `91010000` 至 `91110000`，排序为 `10` 至 `110`（步长 10）。三级页面使用 `AA BB CC 00`，按钮使用所属页面的 `DD=01-99`，角色菜单引用和三个语言脚本同步调整；页面路径、路由名称、组件和服务权限保持不变。
- 系统参数和参数管理同属基础管理：系统参数通过专用表单编辑配置，参数管理维护同一套配置的 Key、类型和值。数据备份和数据归档分别直挂配置、记录、恢复记录三个页面。系统运维包含运行监控、运行日志、缓存查询和数据库迁移记录（原升级历史）；开发工具仅展示接口文档和代码生成。字典数据仍为基础管理下的隐藏页面 `91010700`；代码生成隐藏配置及预览页为开发工具下的 `91110300` 至 `91110600`，代码生成按钮为 `91110201` 至 `91110209`。
- 安全能力：登录管理菜单及其服务、按钮权限只授予平台超级管理员，默认不创建登录策略记录；数据脱敏菜单及默认手机号响应掩码授予系统管理员；OAuth 客户端管理菜单、多因素认证配置和认证方式字典直接写入初始化数据。相关业务表由数据层自动迁移创建。
- 脱敏规则：`base_redact_rule.up.sql` 初始化代码固定支持的全部模板，以及按数据源保存的用户手机号、邮箱、证件号入库策略和按服务名保存的用户列表、分页、详情接口出库策略；管理端通过“数据脱敏”下的脱敏规则、存储脱敏策略和响应脱敏策略页面维护。

`base_area.up.sql` 独立写入行政区划数据，并与 `default_data.up.sql` 一起按文件名参与版本迁移。消息、MFA、OAuth 客户端、语言、翻译和脱敏相关表均由数据层自动迁移创建，SQL 文件不负责建表。

## 多语言数据

三个 `i18n.{locale}.up.sql` 文件各包含当前主数据对应的 `base_i18n` 记录，覆盖系统配置值与名称、字典名称、字典项标签、菜单标题和定时任务名称。`target_type` 的约定为：`1` 配置值、`2` 配置名称、`3` 字典名称、`4` 字典项、`5` 菜单、`6` 定时任务。每条翻译独立插入，主数据文件名排在语言文件之前，确保引用的目标记录先存在。

新增或调整配置、字典、菜单、任务时，要同时检查对应的三个语言脚本和 `README.<locale>.md`，保持 `target_id`、语言代码和主数据一致。

个人信息菜单授予本人登录记录查询权限，服务端固定当前用户与租户；在线会话菜单及下线权限仅供平台超级管理员使用。

租户管理根目录为 `20000000`（排序 20），租户页面为 `20010000`、按钮为 `20010100` 至 `20010400`；用户管理根目录仍为 `30000000`（排序 30）。
