# MySQL デフォルト初期化リソース

このディレクトリでは `v0.0.1` の MySQL 初期化リソースを管理します。SQL は既定データの登録だけを行い、テーブルは作成しません。起動時に GORM の `AutoMigrate` が有効なモデルを作成した後、このディレクトリの `.up.sql` をファイル名順に実行します。

## ファイルの役割

| ファイル | 内容 |
| --- | --- |
| `default_data.up.sql` | 言語、設定、部門、辞書、辞書項目、ジョブ、テナント、メッセージカテゴリ、メニュー、ロール、マスキングルール、マスキングフィールド、マスキングポリシー、開発用アカウントの既定データ。 |
| `base_area.up.sql` | 独立したスクリプトで既定データソースの移行に含まれる行政区画データ。 |
| `i18n.en-US.up.sql` | `en-US` の `base_i18n` 翻訳データ。 |
| `i18n.ja-JP.up.sql` | `ja-JP` の `base_i18n` 翻訳データ。 |
| `i18n.zh-TW.up.sql` | `zh-TW` の `base_i18n` 翻訳データ。 |
| `README.<locale>.md` | 移行説明の各言語版。移行フレームワークが共有翻訳テーブルへ同期します。 |

## 実行と冪等性

起動時は、自動テーブル作成、SQL 移行、移行説明の同期に続けて、OpenAPI、`base_api`、テナントメニュー、Casbin ポリシーを同期します。`default_data.up.sql` と `base_area.up.sql` は外部キー検査を一時的に無効化し、終了時に元の値へ戻します。

初期データはすべて 1 行ずつ `INSERT IGNORE` で登録します。既存の一意キーはスキップされ、業務データを上書きしません。バッチ `INSERT`、`UPDATE`、`DELETE`、`TRUNCATE` は使用しません。`default_data.up.sql` の各テーブルのレコードは `id` の昇順で管理し、新しい既定データは該当する番号帯の位置に追加してください。

`v0.0.1` が記録済みのデータベースでは、初期化ファイルを変更しても移行は再実行されません。変更を確認するときは新しいデータベースを使うか、開発環境の手順で再構築してください。新機能の初期データは引き続き `v0.0.1` に揃え、後続バージョンや既存データ向けの増分スクリプトは追加しません。

## 既定データ

`default_data.up.sql` は現在、次の既定データテーブルへ書き込みます。

`base_language`、`base_config`、`base_dept`、`base_dict`、`base_dict_item`、`base_job`、`base_tenant`、`base_message_category`、`base_menu`、`base_role`、`base_user`、`base_redact_rule`、`base_redact_storage_policy`、`base_redact_output_policy`。

- 言語: `zh-CN`、`zh-TW`、`en-US`、`ja-JP` を用意し、`zh-CN` を主言語にします。
- ログイン時のテナント番号: Admin（`site=2`）とアプリ（`site=3`）の両方でブール設定 `showTenantCode=true` を初期登録し、テナント番号の入力欄を既定で表示します。設定名には英語、繁体字中国語、日本語の翻訳を用意します。
- 基本 ID: 既定テナント、システム部門、5 つのロールテンプレート、ローカル開発用の `super` と `admin` を用意します。初期パスワードは `112233` で、ローカル環境専用です。
- 設定と辞書: Admin とアプリの設定、CAPTCHA、OAuth 自動登録、テナント番号表示、多要素認証のポリシーと方式を含みます。監査ログ登録のフォールバックはフォーム設定 `baseLogFallback`、保持ポリシーは `base_table_archive`、バックアップポリシーは `base_table_backup` に保存し、セッションのライフサイクルとアップロードスキャンは `authn.session`、`oss.upload_security` で設定します。永続辞書にはメニュー、監査、ログインポリシー、メッセージ、権限、コード生成の列挙値を収録します。
- ジョブとメッセージ: ジョブ ID `1000-1004` は、リソース翻訳、メッセージ配信復旧、テーブルアーカイブ、テーブルバックアップ、監査ログ登録フォールバックに対応します。メッセージ配信復旧と監査ログ登録フォールバックは既定で有効、アーカイブとバックアップは無効です。アーカイブ設定は `base_table_archive`、バックアップ設定は `base_table_backup` に保存されます。メッセージカテゴリはシステム、セキュリティ、タスク、業務の 4 種類です。
- メニューと権限：管理画面のルートはホーム、テナント管理、ユーザー管理、システム管理の4つで、モバイルのルートは `99000000` のままです。システム管理には優先順に、基本管理、権限管理、ログイン管理、通知、データマスキング、データバックアップ、データアーカイブ、監査ログ、スケジュールジョブ、システム運用、開発ツールの11個の第2階層ディレクトリを配置します。ID は `91010000` から `91110000`、表示順は `10` から `110`（10刻み）です。第3階層ページは `AA BB CC 00`、ボタンは所属ページの接頭辞と `DD=01-99` を使用します。ロールの参照と3言語の翻訳も更新し、ページパス、ルート名、コンポーネント、サービス権限は維持します。
- 基本管理のページは `91010100` から `91010600` の連番を使用します。システム設定（`91010500`）でキー・種類・値を一元管理します。種類 6 は登録済みフォームを編集画面に読み込み、独立したシステムパラメーター画面は廃止します。データバックアップとデータアーカイブには、それぞれ設定、履歴、復元履歴を直接配置します。システム運用には稼働監視、実行ログ、キャッシュ照会、データベースマイグレーション履歴（旧アップグレード履歴）を配置し、開発ツールには API ドキュメントとコード生成を表示します。辞書データは基本管理の非表示ページ `91010600`、コード生成の非表示設定・プレビューページは開発ツール配下の `91110300` から `91110600`、ボタンは `91110201` から `91110209` です。
- セキュリティ: ログイン管理メニュー、サービス、ボタン権限はプラットフォームのスーパー管理者だけに付与し、ログインポリシーのレコード自体は既定登録しません。マスキングメニューと既定の電話番号レスポンスマスクはシステム管理者に付与します。OAuth クライアント管理メニュー、MFA 設定、認証方式辞書は初期データへ直接登録し、関連テーブルはデータ層が作成します。
- 脱敏ルール: `base_redact_rule.up.sql` はコードが固定対応する全テンプレート、データソース単位で管理するユーザーの電話番号・メール・身分証番号の保存ポリシー、およびサービス名単位で管理するユーザー一覧・ページング・詳細操作の出力ポリシーを初期化します。Admin ではデータマスキング配下のマスキングルール、保存時マスキングポリシー、レスポンスマスキングポリシー画面から管理できます。

`base_area.up.sql` は行政区画データを独立して登録し、`default_data.up.sql` とともにファイル名順で適用します。メッセージ、MFA、OAuth クライアント、言語、翻訳、マスキング関連のテーブルはデータ層が作成し、SQL ファイルではテーブルを作成しません。

## 多言語データ

`i18n.{locale}.up.sql` の 3 ファイルは、それぞれの言語の `base_i18n` レコードを持ちます。対象はシステム設定の値と名称、辞書名称、辞書項目ラベル、メニュータイトル、定期ジョブ名です。`target_type` は `1` 設定値、`2` 設定名称、`3` 辞書名称、`4` 辞書項目、`5` メニュー、`6` 定期ジョブを表します。翻訳は 1 件ずつ登録し、ファイル名順で既定データを言語データより先に適用します。

設定、辞書、メニュー、ジョブを追加・変更するときは、3 つの言語 SQL と対応する `README.<locale>.md` を同時に確認し、`target_id`、言語コード、主データを一致させてください。

個人情報メニューには本人のログイン履歴の参照権限を付与し、ユーザーとテナントは認証情報からサーバー側で確定します。オンラインセッションの一覧と強制ログアウトはプラットフォームのスーパー管理者のみが利用できます。

テナント管理のルートは `20000000`（表示順 20）、ページは `20010000`、操作は `20010100`～`20010400` です。ユーザー管理は `30000000`（表示順 30）のままです。

コード生成はテーブルごとのメニュー権限を `default_data.up.sql` に統合し、新しいバージョンを作成しません。復元時はスクリプトと生成前のメニュー、翻訳、権限を復元し、業務データは変更しません。
