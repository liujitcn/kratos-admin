# デフォルトシステムデータ

デフォルトのテナント、部門、役職、辞書、設定、メニュー、言語、ロール、および開発用の `super`、`admin` アカウントを初期化します。言語の初期データと言語管理メニューは `default_data.up.sql` に統合されています。言語テーブルはデータ層の自動マイグレーションで作成され、共通翻訳テーブルは言語 SQL の適用前に冪等に作成されます。管理画面では言語コード、名称、有効状態、主言語フラグ、並び順を管理し、動的翻訳画面の言語候補は言語管理 API から取得します。

Admin System 画面、AI、コード生成、API ドキュメント、プロジェクトドキュメント、運用監視、実行ログ、およびアプリ共通機能に必要なメニューと保護対象サービスメソッドの権限も設定します。開発ツールのメニューは「運用監視 → 実行ログ → コード生成」の順に並び、実行ログへのアクセス権はデフォルトでスーパー管理者だけに付与します。権限にはリアルタイムコンソール、SSE 購読、履歴ログ検索、元ファイルダウンロードを含みます。モバイルのルートメニューは `999`、ホームは `99901`、マイページは `99909` に固定し、それ以外の第 2 階層 ID は業務モジュール用に予約します。画面設定は `base_menu.meta.app` に保存し、各画面メニューには実際に呼び出す保護対象 API だけを関連付けます。プロジェクトドキュメントはビルド時に収集して Backend バイナリへ埋め込み、プロジェクト識別子は対応する OpenAPI/Swagger ドキュメントの key と一致させます。OAuth 自動登録とテナント番号表示は真偽値設定を使用し、OpenAPI メタデータと Casbin ポリシーは起動時に同期します。

翻訳データは `zh-TW`、`en-US`、`ja-JP` ごとの `i18n.{locale}.up.sql` に分割します。各ファイルは対象言語の `base_i18n` データだけを持ち、`target_type` で辞書名、メニュータイトル、辞書項目ラベル、システム設定の名称と値、定期ジョブ名を区別します。翻訳レコードは 1 件ずつ `INSERT IGNORE` で追加し、ファイル名順により主データを翻訳データより先に適用します。

`base_job` は業務モジュール間で固定 ID 範囲を使用します。kratos-admin は `1000-1999` を使用し、組み込みのリソース翻訳ジョブは `1000` です。後続モジュールは `2000` から開始し、各モジュールに 1,000 件分を予約します。
