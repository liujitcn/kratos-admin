# Default system data

Initializes the default tenant, departments, positions, dictionaries, configuration, menus, languages, roles, and the `super` and `admin` development accounts. Language defaults and the language-management menu are consolidated in `default_data.up.sql`. The data layer creates the language table automatically, and the shared translation table is created idempotently before localized SQL is applied. The Admin UI manages language codes, names, enabled state, primary-language status, and sort order; dynamic translation screens load language options from the language-management API.

The migration also grants the menus and protected service methods required by the Admin System pages, AI, code generation, API documentation, project documentation, operations monitoring, runtime logs, and shared app capabilities. Development Tools are ordered as Operations Monitoring → Runtime Logs → Code Generation. Only the super administrator receives Runtime Logs access by default, including the live-console channel, SSE subscription, historical-log queries, and original-file downloads. The mobile root menu is fixed at `999`, with Home at `99901` and My Account at `99909`; the remaining second-level IDs are reserved for business modules. Page metadata is stored in `base_menu.meta.app`, and each page menu is associated only with the protected APIs it actually calls. Project documents are collected at build time and embedded in the Backend binary. Project identifiers match the corresponding OpenAPI/Swagger document keys. OAuth auto-registration and tenant-number display use boolean configuration, while OpenAPI metadata and Casbin policies are synchronized at startup.

Translation data is split into `i18n.{locale}.up.sql` files for `zh-TW`, `en-US`, and `ja-JP`. Each file contains only its locale's `base_i18n` records and uses `target_type` to distinguish dictionary names, menu titles, dictionary-item labels, system configuration names and values, and scheduled-job names. Every translation uses an individual `INSERT IGNORE`; filename ordering ensures primary data is applied before translations.

`base_job` uses fixed ID ranges across business modules: kratos-admin owns `1000-1999`, and the built-in resource translation job uses `1000`. Subsequent modules start at `2000`, with 1,000 IDs reserved for each module.
